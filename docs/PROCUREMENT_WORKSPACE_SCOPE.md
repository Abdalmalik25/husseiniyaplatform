# Workspace المشتريات — نطاق العمل وحالة الجاهزية

## الهدف

يوفر Workspace المشتريات نقطة تشغيل مستقلة لدورة المشتريات من تعريف البيانات والسياسات وحتى الطلب والاعتماد والاستلام والفاتورة والسداد والتقارير والتحليلات، مع إبقاء المسارات القديمة متاحة للتوافق الخلفي.

## ما تم عزله

تمت إضافة المسار `/procurement-workspace` مع مدخل مستقل في الملاحة. لا يحذف المسار `/procurement` ولا `/requisitions`، ولا يعيد تصميم وحدات المخزون والمحاسبة والموارد البشرية أو ملفات المطورين الآخرين.

## نطاق التشغيل الحالي

| المجال | نقطة الوصول | الحالة |
|---|---|---|
| لوحة الرقابة ومؤشرات الطلبات | `/procurement-workspace` | مضافة |
| البيانات الأساسية | `/basic-data` | تكامل رابط محافظ |
| السياسات والإعدادات | `/settings` | تكامل رابط محافظ |
| طلبات التوريد والاعتماد والاستلام | `/requisitions` | قائمة تشغيل قائمة |
| الموردون وفواتير الشراء والمدفوعات | `/procurement` | قائمة تشغيل قائمة |
| المستندات والتدقيق | `/audit` وملحقات الكيانات | تكامل رابط محافظ |
| التقارير وذكاء الأعمال | `/reports` و`/analytics` | تكامل رابط محافظ |

## عقود التكامل

تعتمد لوحة Workspace على إجراءات `erp.listProcurements` و`erp.getProcurementKpis` و`supplier.list` فقط. لا تعتمد على `modulesRouter`، وذلك لتقليل أثرها على الوحدات التي يعمل عليها مطورون آخرون.

## نتيجة التحقق

نجح بناء الإنتاج `pnpm build` بعد إضافة Workspace. فحص TypeScript الشامل متوقف حالياً بسبب خطأ JSX مستقل في `client/src/pages/Inventory/InventoryValuationPanel.tsx` عند وسم `</Tabs>`، وهو ملف خارج نطاق هذه الوحدة ولم يتم تعديله منعاً للتعارض مع المطور المسؤول عنه.

## ملاحظة إنتاجية

لا تُعتبر المنظومة كلها جاهزة للإطلاق النهائي قبل إصلاح خطأ المخزون وتشغيل `pnpm check` و`pnpm test` كاملاً، ثم اختبار الصلاحيات والمرفقات وقواعد الاعتماد في بيئة بيانات اختبارية غير إنتاجية.
