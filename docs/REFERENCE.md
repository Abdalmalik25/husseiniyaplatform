# الوثائق المرجعية — نظام ALHUSAINIA للحسابات والمخازن والمتجر الإلكتروني

> وثيقة معتمدة للبنية والقرارات المعمارية وطرق الربط والنشر.
> تاريخ الاعتماد: أغسطس 2026 — المستودع: `husseiniya-platform` (النسخة المطوَّرة الفعّالة).

---

## 1. القرار المعماري المعتمد: فصل كامل + ربط برابط + قاعدة بيانات موحدة

| المكوّن | الاستضافة | الدور | الربط |
|---|---|---|---|
| **الموقع الإلكتروني** | وكالة/استضافة PHP أو WordPress | تعريف وتسويق فقط | زر / إطار → المتجر |
| **منصة ALHUSAINIA** | Vercel (النظام + المتجر) | حسابات، مخازن، مبيعات، طلبات، متجر | نفس قاعدة البيانات |
| **قاعدة البيانات** | Neon (Postgres موحّد) | المصدر الوحيد للصحة (single source of truth) | — |

**مبررات الفصل:**
1. عزل الحماية: الموقع العام لا يلمس أي إجراء محمي (تسجيل دخول الإدارة بعيد تماماً عن زيارة الموقع).
2. نشر مستقل: تحديث الموقع لا يؤثر على النظام، والعكس.
3. أداء: الموقع البسيط لا يتحمل ثقل أدوات الإدارة؛ المتجر SPA خفيفة على صفحة مستقلة.
4. صحة البيانات: لا مزامنة مضاعفة — طلبات الموقع تدخل مباشرة كطلبات «قيد الانتظار» في نفس قاعدة بيانات النظام.

**الربط بثلاث طرق (اختيار واحدة أو أكثر):**
1. **زر/رابط**: `الموقع → /store` (يفتح المتجر كاملاً) — الأبسط والأفضل للجوال.
2. **إطار iframe**: عبر `Store.php` في نفس صندوق الموقع.
3. **API مباشر**: قراءة الكتالوج وإرسال الطلبات من صفحات الموقع نفسه عبر `SyncJav.js` أو fetch عادي.

## 3. قواعد البيانات (المرجع)

المخطط الكامل في `drizzle/schema.ts`. الجداول الحاسمة للربط:

| الجدول | الدور الحاسم |
|---|---|
| `products` | صنف/خدمة — `isActive` يتحكم بالظهور في المتجر، `currentStock` يُخصم آلياً |
| `customers` | عملاء — عميل المتجر يُنشأ تلقائياً برمز `WEB-...` |
| `orders` / `orderItems` | طلبات التوزيع والمتجر — رقم الطلب يبدأ بـ `WEB-` |
| `inventoryMovements` | حركة المخزون — كل طلب متجر يكتب حركة `out` |
| `accounts` / `transactions` / `openingBalances` | الدليل المحاسبي والقيد المزدوج والأرصدة الافتتاحية |
| `payments` | دفعات الفواتير وسندات القبض/الصرف |

> ترحيلات التغييرات: `npm run db:push` (drizzle-kit generate + migrate).

## 4. واجهات التكامل مع الموقع (REST — عامة عمداً)

كلها تحت `/api/web/*` مع CORS مفتوح (`Access-Control-Allow-Origin: *`) لإتاحة الربط من أي نطاق.

| النقطة | الطريقة | الوصف | الرد |
|---|---|---|---|
| `/api/web/catalog` | GET | الكتالوج (بحث/تصنيف) | `{ ok, items[], categories[] }` |
| `/api/web/place-order` | POST | إرسال طلب (بدون تسجيل) | `{ ok, orderId, orderNumber }` |
| `/api/health` | GET | فحص حيوية الخدمة (أيضاً مهمة cron يومية) | `{ ok, service, version }` |

**أمثلة بالجافاسكربت (من أي موقع):**
```js
// قراءة الكتالوج
const cat = await fetch("https://BASE/api/web/catalog").then(r => r.json());
// إرسال طلب
const res = await fetch("https://BASE/api/web/place-order", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    customerName: "أحمد محمد", customerPhone: "771234567", deliveryAddress: "صنعاء - ...",
    items: [{ productId: 3, quantity: 2 }]
  })
}).then(r => r.json());
```

**نفس النقاط متاحة عبر tRPC داخل التطبيق:** `store.catalog` و `store.placeOrder` (في `routers.ts`) يستدعيان نفس المنطق في `server/webStore.ts` — **فإنشاء طريقة جديدة لا يتطلب سوى تعديل مكان واحد**.

## 5. دورة الطلب الإلكتروني (المرجع)

```
الموقع الإلكتروني                        منصة ALHUSAINIA
      │                                         │
      │  زر / iframe → /store                    │
      ├──────────────────────────────────────────►  صفحة المتجر (Store.tsx)
      │                                          │
      │  العميل يختار ويتم الطلب                   │
      │  store.placeOrder / /api/web/place-order  │
      └──────────────────────────────────────────►  1) تحقق من المخزون
                                                  │  2) معاملة واحدة (transaction):
                                                  │     - إنشاء/استرداد عميل WEB-
                                                  │     - إنشاء طلب WEB-... حالة pending
                                                  │     - خصم المخزون + حركة out
                                                  │  3) رد: رقم الطلب
      ◄──────────────────────────────────────────┤
      شاشة نجاح + مشاركة واتساب                    │
                                                  │
  لوحة الإدارة (Commercial.tsx ← الطلبات)          │
  - طلبات WEB- موسومة «متجر إلكتروني»              │
  - الموظف: مؤكد ← معالجة ← شحن ← توصيل           │
  - عند التأكيد: فاتورة مبيعات وقيود محاسبية       │
```

**قواعد حوكمة المخزون:** الطلب العام يخصم فوراً (reservation)؛ الإلغاء من اللوحة يعيد الكمية عبر آليات الإلغاء الحالية في المشتريات/المبيعات.

## 6. الأمان والصلاحيات (المرجع)

| الوجهة | الصلاحية |
|---|---|
| `/api/web/*` + `store.*` + صفحات `/store` و `/` و `/download` | عامة بلا تسجيل (متعمدة) |
| بقية مسارات tRPC | `protectedProcedure` — مطلوب تسجيل دخول وجلسة صالحة |
| مسارات `/commercial` و `/reports` | تُحمى في الواجهة بواسطة `useAuth` |

> أضف أي إجراء جديد افتراضياً بـ `protectedProcedure`؛ اجعل الإجراء عاماً فقط إذا خدم المتجر/الموقع (مثل قراءة الكتالوج وإرسال الطلب).

## 7. النشر (المرجع)

- **البناء:** `npm run dev` للتطوير — `npm run build` للبناء (vite → `dist/public` + esbuild → `api/index.mjs`).
- **Vercel:** كل شيء في `vercel.json` (rewrite `/api/*` → الوظيفة، باقي المسارات → SPA). متغيرات البيئة في `.env` مثالها في `.env.example` (أهمها `DATABASE_URL`).
- **الفحص:** `npm run check` (tsc) — و`npm run test` (vitest).
- **الموقع الخارجي:** ارفع `client/public/Store.php` و`SyncJav.js` (يُنسخان تلقائياً لـ `dist/public` مع البناء) إلى استضافة موقعك.

## 8. دليل التطوير السريع

1. أي جدول جديد → أضفه في `drizzle/schema.ts` ثم `npm run db:push`.
2. أي إجراء خادم جديد → في `routers.ts` (روتر موجود) أو روتر جديد أسفل `appRouter`.
3. منطق المتجر المشترك → في `server/webStore.ts`.
4. أي صفحة جديدة → `client/src/pages/*.tsx` + مسار في `client/src/App.tsx` (lazy import).
5. بعد كل تعديل: `npm run check` قبل الرفع.

## 10. ميزات الترقية (الإقفالات + الأرصدة + استيراد/تصدير)

### إقفال الدورة (تبويب «الدليل الشجري» في Home)
1. **معاينة**: `accounting.closing.preview` يحسب أرصدة كل حساب = الأرصدة الافتتاحية للفترة + الحركات حتى تاريخ الإقفال (باستثناء المقبوضات العكسية وقيد الإقفال نفسه)، ويعرض الإيرادات والمصروفات وصافي النتيجة.
2. **تنفيذ**: `accounting.closing.execute` ينشئ قيود إقفال (مرجع `closing`) بمعاملة واحدة:
   - الإيرادات → مدين، والمصروفات → دائن، والطرف المقابل حساب النتائج/رأس المال (افتراضياً 3010).
   - **حماية التكرار**: يرفض الإقفال إذا وُجد قيد إقفال بنفس اسم الدورة.
   - يكتب سجل نشاط ويوازن المدين/الدائن قبل الاعتماد.

### الأرصدة الافتتاحية
- **مالية**: `accounting.getOpeningBalances` + `saveOpeningBalances` (حسب `periodName` + `accountId` — upsert).
- **مخزنية**: عبر «تعديل المخزون» (زر الحقيبة على بطاقة المنتج) بنوع `adjustment`، أو عبر استيراد CSV (الرصيد يُحدَّث بفارق الرصيد مع حركة جرد).

### استيراد/تصدير الأصناف والخدمات (تبويب «المنتجات والمخازن»)
- **تصدير CSV**: الأصناف الحالية (بما فيها `type`: صنف/خدمة، الأسعار، حد الإنذار، الرصيد) بترميز UTF-8-BOM متوافق مع Excel.
- **استيراد CSV**: رؤوس إنجليزية أو عربية، تحديث بالرمز `code`، إضافة الجديد، وتعديل المخزون بفارق الرصيد. حد أقصى 500 صف، مع تقرير (أُضيف/حُدّث/أخطاء).

### تحسينات الأداء والتفاعل (2026-08)
- `staleTime: 60_000` + `refetchOnWindowFocus: false` على قوائم Commercial وHome وReports وكتالوج المتجر.
- بحث المتجر عبر `useDebounce` (350ms) لمنع إطلاق الطلبات عند كل حرف.
- أزرار بتحميل (Loader2) وإشعارات sonner لكل العمليات الجديدة.

### دورة حياة طلب المتجر الكاملة (v1.2.0)
1. الطلب من الموقع → `pending` مع حجز المخزون (حركة `out` مرجع `order`).
2. **زر «فاتورة مبيعات»** في تبويب الطلبات (للطلبات `WEB-` فقط):
   - `orders.createSaleInvoice` ينشئ فاتورة رسمية `SI-...` من أصناف الطلب، **دون خصم مخزون ثانٍ**.
   - يحدد الحالة: مدفوعة / مدفوعة جزئياً (يراكم الرصيد على العميل) / مؤكدة (آجل).
   - يمرر القيود عبر `postInvoiceGlEntries` (صندوق/ذمم + إيراد مبيعات 4010) ويسجل سجل نشاط.
   - **حماية التكرار**: يرفض إذا وُجدت فاتورة مرتبطة بنفس رقم الطلب.
3. مورد الموقع: **webhook** `ORDER_WEBHOOK_URL` (اختياري) يُرسل JSON بالطلب فور إنشائه (Slack/واتساب غيتواي...) — يُضبط في `.env`.
